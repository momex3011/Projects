# Website Builder

A claymorphism-styled website builder built with Next.js for the frontend and prepared to run behind Flask for Python-friendly hosting.

## Stack

- Next.js App Router for the exported frontend
- React + Zustand for the builder state
- Tailwind CSS v3 plus custom claymorphism utilities
- `@dnd-kit/core` and `react-rnd` for drag, nesting, and resizing
- Flask + Flask-SQLAlchemy for serving the exported app and persisting project data

## Project Structure

```text
my-website-builder/
├── app.py                    # Flask app that serves the exported frontend + /api routes
├── models.py                 # SQLAlchemy models for users and projects
├── wsgi.py                   # WSGI entrypoint for Python hosts
├── requirements.txt          # Flask runtime dependencies
├── data/                     # SQLite database and future upload assets
├── public/
├── src/
│   ├── app/
│   ├── components/
│   ├── lib/
│   ├── store/
│   └── styles/
└── out/                      # Generated by `npm run build`
```

## Frontend Development

Install the frontend dependencies and run the Next.js dev server:

```bash
npm install
npm run dev
```

Open `http://localhost:3000`.

## Flask Deployment Flow

The frontend is configured for static export so Flask can serve the generated files directly.

### 1. Build the frontend export

```bash
npm run build
```

This generates the static site in `out/`.

### 2. Create a Python environment

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Run Flask locally

```bash
python app.py
```

Or use:

```bash
npm start
```

The Flask server runs on `http://localhost:5000` by default and serves:

- `/`
- `/builder/`
- `/backend-view/`
- `/api/health`
- `/api/projects`

## Environment Variables

Copy `.env.example` if you want to customize Flask behavior.

- `FLASK_PORT`: Flask port, default `5000`
- `FLASK_DEBUG`: set to `1` for debug mode
- `FRONTEND_DIR`: override the exported frontend directory
- `PROJECT_DATA_DIR`: override where the SQLite file and future backend assets are stored
- `DATABASE_PATH`: override the SQLite database path
- `DEFAULT_USERNAME`: default local-development username used when no auth exists yet

## Flask API

### `GET /api/health`

Returns the Flask health status plus whether the exported frontend was found.

### `GET /api/projects`

Returns the saved projects for a user from SQLite. You can pass `?username=local-builder` or `?project_id=<id>`.

### `POST /api/projects`

Accepts a JSON project payload and stores it in SQLite. The backend creates a `User` and `Project` record when needed.

## Notes

- The builder itself still works fully client-side through Zustand persistence in the browser.
- Backend persistence now uses SQLite via Flask-SQLAlchemy instead of filesystem JSON snapshots.
- Flask is now the correct runtime target for deployment instead of `next start`.
- The old Next.js API route was removed because static export and App Router API routes do not deploy together in this Flask setup.
